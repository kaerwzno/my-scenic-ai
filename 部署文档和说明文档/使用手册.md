# 使用手册

本文说明系统启动后的主要使用流程，覆盖微信小程序游客端和 Web 管理端。

## 重要说明：请从可执行文件目录运行

本项目提交材料中包含 `可执行文件`、`源代码`、`部署文档和说明文档` 三部分。

实际运行、演示和评测时，请使用：

```text
提交材料\可执行文件\灵山AI导游系统
```

`提交材料\源代码` 目录仅用于查看代码，里面不包含模型权重、知识图谱数据、向量库、数据库、数字人素材等运行资产。若从 `源代码` 目录启动，知识库问答、图谱问答测试和数字人服务可能无法正常工作。

## 1. 访问入口

系统服务启动后，常用入口如下：

| 端 | 入口 | 说明 |
| --- | --- | --- |
| 微信小程序 | 微信开发者工具打开 `可执行文件/灵山AI导游系统/miniprogram` | 游客端导览、问答、路线、景点详情 |
| Web 管理端 | `http://127.0.0.1:5173` | 数据看板、知识库、图谱、图谱问答测试、数字人、报表 |
| 后端接口 | `http://127.0.0.1:8000/api/health/` | 后端健康检查 |
| 数字人控制台 | `http://127.0.0.1:8010/dashboard.html` | 数字人服务控制台 |

本地调试时，微信开发者工具需要在“详情 / 本地设置”中勾选“不校验合法域名、web-view、TLS 版本以及 HTTPS 证书”。

## 2. 使用前检查

正式演示或评测前，建议先完成以下检查：

1. 后端健康检查能打开：

   ```text
   http://127.0.0.1:8000/api/health/
   ```

2. RAG 就绪检查返回 `ready: true`：

   ```text
   http://127.0.0.1:8000/api/rag/ready/
   ```

3. 管理端能打开并进入看板：

   ```text
   http://127.0.0.1:5173
   ```

4. 微信开发者工具能正常编译 `提交材料\可执行文件\灵山AI导游系统\miniprogram`。

5. 如需演示数字人，数字人控制台能打开：

   ```text
   http://127.0.0.1:8010/dashboard.html
   ```

如果其中任一步失败，先参考《环境配置说明.md》检查对应服务是否启动。

## 3. 微信小程序游客端

### 3.1 登录与偏好选择

打开小程序后进入登录页，可选择微信登录或游客模式。

登录页支持设置游玩偏好：

- 游玩偏好：文化古迹、亲子互动、自然风光、网红打卡、特色美食、深度体验。
- 游玩时间：`<2 小时`、`2-4 小时`、`>4 小时`。
- 出行同伴：情侣、家庭、朋友、独自。
- 行程强度：适中、轻松、紧凑。

偏好会用于后续路线推荐和导览问答。

推荐演示方式：

1. 选择 2-3 个游玩偏好，例如“文化古迹”“自然风光”。
2. 选择游玩时间，例如 `2-4 小时`。
3. 选择出行同伴和行程强度。
4. 点击游客模式或微信登录进入小程序。
5. 进入后观察路线推荐和问答内容是否贴合所选偏好。

### 3.2 AI 导游问答

底部导航进入“导游”页。

可使用以下方式提问：

- 点击快捷问题，例如“3 小时路线”“灵山大佛”等。
- 在输入框中输入景区相关问题。
- 允许麦克风权限后，可使用语音提问。

系统会结合本地景区知识库和大模型生成回答。常见可测试问题：

- “帮我规划 3 小时精华路线。”
- “灵山大佛有多高？参观重点和礼仪有哪些？”
- “第一次来灵山，半天时间怎么安排？”
- “梵宫适合什么时候去？”

问答结果可重点观察：

- 是否围绕灵山景区本地知识回答。
- 是否避免编造明显不存在的景点或服务。
- 回答是否简洁、适合作为导游口播。
- 弱网或后端异常时是否有错误提示或兜底内容。

导游页支持数字人模式。开启后，页面会展示数字人讲解区域，并在问答时播放数字人演示视频或待机视频。数字人模式适合用于展示“文字问答 + 形象讲解”的游客体验。

### 3.3 游览路线

底部导航进入“游览”页。

该页面展示推荐路线，包含：

- 路线名称与预计时长。
- 适合人群和路线标签。
- 景点节点列表。
- 当前导览状态。

可执行操作：

- 切换不同推荐路线。
- 点击景点节点进入景点详情页。
- 开始路线导览。
- 生成当前景点语音讲解。
- 切换到下一站。

推荐演示方式：

1. 打开“游览”页，查看默认推荐路线。
2. 切换不同路线，观察路线时长、标签和景点顺序。
3. 点击某个景点节点进入详情页。
4. 返回路线页后点击开始导览。
5. 选择某一站生成语音讲解，检查播放状态。

### 3.4 景点详情

从路线页或问答页点击景点可进入景点详情。

详情页展示：

- 景点名称。
- 景点介绍。
- 游览提示。
- 与路线关联的导览信息。

如果当前景点支持语音讲解，可点击播放讲解音频。生成失败时可重试。

### 3.5 我的与历史记录

底部导航进入“我的”页。

该页面展示用户信息、游玩成就和常用入口：

- 我的路线：跳转到路线页。
- 历史记录：查看历史问答、路线和识别记录。
- 游玩反馈：当前为预留入口。

历史记录页支持：

- 查看历史交互。
- 点击路线记录回到路线页。
- 点击景点识别记录进入景点详情。
- 删除历史记录。

推荐演示方式：

1. 先在导游页完成 1-2 次问答。
2. 再在路线页查看或进入景点详情。
3. 打开“我的 / 历史记录”，检查刚才的交互是否记录。

## 4. Web 管理端

### 4.1 登录

浏览器打开：

```text
http://127.0.0.1:5173
```

进入登录页后，填写用户名和密码并点击“登录”即可进入后台。当前登录为演示模式，账号密码不做强校验。

### 4.2 数据看板

进入后台默认显示“数据看板”。

看板展示：

- 今日服务人次。
- 累计交互总数。
- 本地 RAG 命中率。
- 平均响应延迟。
- 近 7 天游客交互趋势。
- 热门提问景区分布。
- 游客对话情绪占比。

该页面用于查看系统整体运行效果和游客交互情况。

推荐演示方式：

1. 先通过小程序产生几条问答或路线记录。
2. 回到管理端刷新看板。
3. 观察服务人次、交互总数、RAG 命中率和平均响应延迟。
4. 查看近 7 天趋势、热门景区分布和情绪占比图表。

这些数据可用于说明系统稳定性、响应延迟和游客交互效果。

### 4.3 知识库管理

进入“知识库管理”页面。

主要功能：

- 查看已入库文档列表。
- 上传 Markdown 或文本文件。
- 查看文档类型、大小、状态和上传时间。
- 触发文档解析、语义分块、知识实体抽取和向量化入库流程。

上传文档后，页面会展示处理进度。处理完成后，游客端问答会优先命中新知识。

推荐演示方式：

1. 打开知识库管理页。
2. 查看当前已入库文档列表。
3. 点击“上传文档”，选择 Markdown 或文本文件。
4. 观察“解析文档结构、语义分块、抽取知识实体、向量化入库”的处理进度。
5. 上传完成后，到小程序或“图谱问答测试”页面提问验证新知识是否生效。

### 4.4 知识图谱可视化

进入“知识图谱”页面。

主要功能：

- 查看 LightRAG 内部实体关系图谱。
- 调整最小度数。
- 调整最大节点数。
- 刷新图谱数据。

如果页面提示暂无图谱数据，需要先完成知识库入库并生成图谱文件。

推荐演示方式：

1. 打开“知识图谱”页面。
2. 点击“刷新图谱数据”。
3. 调整“最小度数”和“最大节点”，观察图谱节点变化。
4. 选择几个核心实体，例如灵山大佛、九龙灌浴、梵宫，查看它们与其他实体的关系。

### 4.5 图谱问答测试

进入管理端左侧导航栏的“图谱问答测试”页面。

使用方式：

1. 在测试问题输入框中输入问题。
2. 点击“图谱增强回答”。
3. 查看回答结果、模型信息、图谱实体统计和证据链。

该页面用于验证系统是否能从知识图谱中找到实体关系证据，并结合大模型生成回答。

该页面也是非功能性需求中“本地景区知识库”和“事实性问答准确率”指标的主要测试入口。测试时可使用标准问题集逐条提问。

评测重点：

- 回答是否命中景区知识库事实。
- 回答是否给出图谱证据链。
- 页面顶部是否显示图谱实体和关系统计。
- 回答是否在合理时间内返回。
- 是否出现接口错误、长时间无响应或空结果。

推荐测试问题：

- “灵山大佛有多高？”
- “九龙灌浴表演有什么看点？”
- “半天时间游览灵山怎么安排？”
- “梵宫和灵山大佛之间适合怎么衔接？”
- “亲子游客适合优先看哪些景点？”

详细测试步骤见同目录下：

```text
知识库问答测试说明.md
```

### 4.6 数字人形象与语音配置

进入“数字人”页面。

主要功能：

- 开启或关闭小程序数字人功能。
- 设置数字人名称。
- 选择数字人形象。
- 选择服装配置。
- 设置 Qwen TTS 音色。
- 编辑默认开场白。
- 保存配置。
- 生成开场白测试视频。

可选音色包括 Cherry、Bella、Stella、Ethan、Brian、Henry，以及部分方言音色。

其中演示形象使用预制视频，不依赖本机 GPU；真实形象生成会调用本机数字人服务。

推荐演示方式：

1. 打开“数字人配置”页面。
2. 检查功能状态是否开启。
3. 选择数字人形象、服装和音色。
4. 修改默认开场白。
5. 点击保存配置。
6. 点击生成开场白测试视频。
7. 若生成失败，检查数字人服务和 GPU PyTorch 环境。

### 4.7 报表分析

进入“报表”页面。

报表页用于查看游客交互后的统计分析，包括趋势图、分布图和近期活动记录。若系统交互样本不足，页面会提示暂无足够数据。

## 5. 非功能性指标测试入口

| 指标 | 推荐测试入口 | 观察点 |
| --- | --- | --- |
| 本地景区知识库 | 管理端“知识库管理”“图谱问答测试” | 文档入库状态、问答是否命中本地知识 |
| 事实性问答准确率 | 管理端“图谱问答测试”、小程序“导游”页 | 标准问题回答是否正确、是否有证据链 |
| 响应延迟 | 管理端“数据看板”、问答页面实际返回速度 | 平均响应延迟、是否长时间无响应 |
| 系统稳定性 | 一键启动脚本、管理端、小程序连续操作 | 是否崩溃、接口是否报错、服务是否持续可用 |
| 数字人自然度 | 管理端“数字人配置”、小程序数字人模式 | 语音、口型、视频播放是否自然 |

其中“事实性问答准确率”建议使用 `知识库问答测试说明.md` 中的问题表逐条测试，并记录正确、部分正确、错误三类结果。

如果需要用程序批量测试，可参考 `知识库问答测试说明.md` 中的 API 说明和 `api_qa_test.py`。

## 6. 演示推荐流程

推荐按以下顺序演示：

1. 打开后端健康检查，确认后端正常。
2. 打开 Web 管理端，查看数据看板。
3. 在知识库管理页上传或查看文档。
4. 打开知识图谱页，展示实体关系。
5. 点击左侧导航栏“图谱问答测试”，输入景区问题并查看回答、图谱统计和证据链。
6. 打开数字人配置页，展示形象、音色和测试视频。
7. 使用微信开发者工具打开小程序。
8. 以游客身份进入小程序，选择偏好。
9. 在导游页提问。
10. 在游览页查看推荐路线并进入景点详情。
11. 在我的页查看历史记录。

## 7. 常见状态说明

| 现象 | 说明 |
| --- | --- |
| 小程序请求失败 | 检查后端是否启动，确认小程序本地调试已关闭合法域名校验 |
| 管理端空数据 | 初始状态交互数据较少，可先在小程序产生问答和路线记录 |
| RAG 未就绪 | 执行环境配置文档中的 RAG 初始化命令 |
| 图谱无数据 | 先通过知识库完成文档入库和图谱生成 |
| 找不到图谱问答测试入口 | 在管理端左侧导航栏点击“图谱问答测试” |
| 数字人生成失败 | 检查 `digital-human-service` 是否启动、PyTorch 是否为 GPU 版 |
| 语音不可用 | 检查小程序麦克风授权、后端 TTS/ASR 配置和网络状态 |

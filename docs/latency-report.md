三个数分开看，因为它们差一个数量级，混在一起报哪个都不对。

| 指标 | 含义 | 用户体感 |
|---|---|---|
| **首字延迟** | 点发送 → 屏幕上第一次出现东西 | 「它理我了」 |
| **完整延迟** | 点发送 → 完整答案出现 | 「它答完了」 |
| **检索耗时** | 知识库插件自己花的时间 | 用户看不到，但决定了瓶颈在哪 |

## 三、这些数字怎么用

1. 论文里报**两个**延迟，别只报一个：首字延迟（有没有反应）和完整延迟（答案多久到）。
2. 检索耗时单独列，用来说明「慢的不是检索，是大模型」——这直接引出优化方向。
3. 闲聊和查库分开报，两者的差距就是「查知识库的代价」。
4. 想改进的话，按这个顺序：先减大模型往返次数（意图判断别交给大模型），再考虑流式输出接语音合成，最后才是换模型。

## 二、卡住的地方

### 2.1 图片宽高比不被接受（`InvalidParameter.Ratio`）

用**公开可访问的真人照片 URL**（GitHub 上的 lena.jpg，512×512）测试，
错误是 `Ratio: request parameter is invalid` ——
说明 URL 读到了、检查走完了，**卡在宽高比**。

我们的立绘是 1024×1024（1:1），大概率就是被这条挡住的。

> 注意：我们试过 3:4 / 9:16 / 2:3 的裁图，但**那些图是通过 oss:// 传的，
> 根本没走到比例检查**（见下一条），所以「哪些比例可用」这个问题还没真正测过。

### 2.2 上传的文件服务读不到（`InvalidParameter.DataInspection`）

所有 `oss://` 写法都报同一个错：

```
oss://<key>                          -> DataInspection
oss://dashscope-file-mgr/<key>       -> DataInspection
oss://dashscope-file-mgr.oss-.../<key> -> DataInspection
```

而同一个文件、同一个模型，换成公开 HTTPS URL 就能通过检查（错误变成 `Ratio`）。

**所以 `DataInspection` 的含义是「我读不到这个媒体」**，不是「格式不对」。
也就是说：**`oss://` 这个引用方式，这个接口不认。**

（推测：可能 `oss://` 只对部分模型开放，或者需要带签名的临时 URL。
这一步需要文档。）

## 三、三种错误码的含义（实测归纳，很有用）

排查过程中摸清了 DashScope 这套接口的错误码含义，以后遇到能直接判断：

| 错误 | 含义 | 我们遇到它的场景 |
|---|---|---|
| `url error, please check url` | **路由或模型不存在** | 试错路径时 |
| `Model not exist` | 模型名不对 | 试 `face-detect` 当模型名 |
| `AccessDenied`（403） | 模型存在但账号没权限 / 调用方式不对 | `emo-detect`（少了 `-v1`）；同步调异步接口 |
| `InvalidURL` | URL 打不开（404） | 猜的示例图地址 |
| `DataInspection` | **媒体读不到** | 传 `oss://` |
| `Ratio` | **宽高比或参数不合法** | 传公开的 1:1 真人照 |
| `xxx should not be null` | **路由和模型都对，缺参数** | 用来判断接口是否存在（最有用的一招）|

> 最后一招是本次排查的主力：**拿「缺参数」的报错反证接口存在**。
> 看到 `image_url should not be null` 就能确定路由对，比看文档还准。
